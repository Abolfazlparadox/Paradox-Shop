# چک‌لیست امنیتی استقرار در محیط پروداکشن (Production Security Checklist)

> **پروژه**: فروشگاه پارادوکس (Paradox Shop)  
> **سند مرجع**: الزامات انطباق با OWASP ASVS و استانداردهای امنیت عملیاتی  
> **وضعیت**: آماده‌سازی نهایی برای بهره‌برداری پروداکشن  

---

## ۱. تنظیمات بنیادین جنگو و وب سرور (Django & Web Server)

- [x] **متغیر `DJANGO_DEBUG`**: در پروداکشن الزاماً برابر `False` تنظیم شود. سیستم به صورت خودکار در صورت عدم وجود این شرط پیکربندی ناامن را رد می‌کند.
- [x] **کلید مخفی `DJANGO_SECRET_KEY`**: مقداردهی شده با یک رشته تصادفی حداقل ۵۰ کاراکتری غیرقابل حدس. مقادیر پیش‌فرض یا شامل "dev" موجب پرتاب `ImproperlyConfigured` می‌شود.
- [x] **دامنه و میزبان‌ها (`DJANGO_ALLOWED_HOSTS`)**: تعیین دقیق نام دامنه‌ها (مانند `api.paradoxshop.com`). استفاده از کاراکتر ستاره (`*`) در پروداکشن با ارور متوقف می‌شود.
- [x] **سیاست CORS (`CORS_ALLOWED_ORIGINS`)**: تعیین صریح دامنه‌های مجاز فرانت‌اند (مانند `https://paradoxshop.com`). متغیر `CORS_ALLOW_ALL_ORIGINS` در پروداکشن `False` است.
- [x] **محدودیت حجم آپلود**: `DATA_UPLOAD_MAX_MEMORY_SIZE` و `FILE_UPLOAD_MAX_MEMORY_SIZE` روی ۱۰ مگابایت تنظیم شده‌اند تا از حملات پرکردن حافظه رم جلوگیری شود.

---

## ۲. هدرهای امنیتی و پروتکل ارتباطی (HTTPS & Security Headers)

- [x] **اجبار SSL/TLS (`SECURE_SSL_REDIRECT = True`)**: هدایت خودکار ترافیک ناامن HTTP به HTTPS.
- [x] **هدر HSTS (`SECURE_HSTS_SECONDS = 31536000`)**: الزام مرورگر به برقراری ارتباط صرفاً با HTTPS به مدت حداقل یک سال.
- [x] **زیردامنه‌های HSTS (`SECURE_HSTS_INCLUDE_SUBDOMAINS = True`)**: اعمال اجبار SSL روی تمام زیردامنه‌ها.
- [x] **بارگذاری اولیه HSTS (`SECURE_HSTS_PRELOAD = True`)**: امکان ثبت دامنه در لیست پیش‌بارگذاری مرورگرها.
- [x] **محافظت در برابر Clickjacking (`X_FRAME_OPTIONS = "DENY"`)**: جلوگیری از بارگذاری صفحات در iframe.
- [x] **محافظت از تشخیص خودکار MIME (`SECURE_CONTENT_TYPE_NOSNIFF = True`)**: مهار حملات MIME-confusion.
- [x] **هدر امنیتی پروکسی معکوس (`SECURE_PROXY_SSL_HEADER = ("HTTP_X_FORWARDED_PROTO", "https")`)**: هماهنگی صحیح با Nginx یا لودبالانسر ابری.

---

## ۳. کوکی‌ها و توکن‌ها (Cookies & Tokens)

- [x] **پرچم `SESSION_COOKIE_SECURE = True`**: ارسال کوکی‌های سشن منحصراً از طریق بستر رمزنگاری‌شده HTTPS.
- [x] **پرچم `CSRF_COOKIE_SECURE = True`**: ارسال کوکی توکن CSRF منحصراً از طریق HTTPS.
- [x] **پرچم `SESSION_COOKIE_HTTPONLY = True`**: عدم دسترسی اسکریپت‌های کلاینت به کوکی‌های سشن.
- [x] **ویژگی `SameSite`**: مقداردهی شده به `Lax` برای محافظت در برابر جعل درخواست میان‌وبگاهی (CSRF).
- [x] **چرخش رفرش‌توکن JWT (`ROTATE_REFRESH_TOKENS = True`)**: ابطال و جایگزینی خودکار توکن رفرش با هر بار فراخوانی.
- [x] **بلک‌لیست توکن (`rest_framework_simplejwt.token_blacklist`)**: ثبت پایگاه داده‌ای توکن‌های ابطال‌شده پس از لاگ‌اوت یا چرخش.

---

## ۴. احراز هویت و کنترل دسترسی (Auth & RBAC)

- [x] **محدودسازی نرخ درخواست (Rate Limiting)**:
  - ورود: حداکثر ۱۰ درخواست در دقیقه به ازای IP.
  - ثبت‌نام: حداکثر ۵ درخواست در دقیقه.
  - درخواست و تایید OTP: حداکثر ۱۰ درخواست در دقیقه.
  - فراموشی رمز عبور: حداکثر ۵ درخواست در دقیقه.
- [x] **ضد Brute-Force کدهای OTP**: باطل‌سازی خودکار و حذف از ردیس پس از ۵ بار تلاش نادرست متوالی.
- [x] **قفل حساب کاربری**: قفل خودکار ۳۰ دقیقه‌ای پس از ۵ بار تلاش متوالی ورود با پسورد اشتباه.
- [x] **عدم افشای وجود کاربر (Anti-Enumeration)**: پاسخ‌های همسان در فرایند بازنشانی رمز عبور.
- [x] **پرمیشن‌های سمت سرور ادمین**: اجبار `IsStaffAdmin` و `IsPromotionAdmin` روی کلیه اندپوینت‌های `/api/v1/admin/*`.
- [x] **کنترل دسترسی شیء‌محور (IDOR Prevention)**: فیلتر سفارشات، پرداخت‌ها و آدرس‌ها منحصراً بر اساس `user=request.user`.

---

## ۵. امنیت بارگذاری فایل‌ها و رسانه‌ها (File Uploads)

- [x] **سقف حجم فایل**: حداکثر ۵ مگابایت برای هر تصویر.
- [x] **فیلتر فرمت و پسوند**: پذیرش صرفاً پسوندهای معتبر `.jpg`, `.jpeg`, `.png`, `.webp`.
- [x] **کنترل Decompression Bomb**: تنظیم `Image.MAX_IMAGE_PIXELS = 10_000_000` در Pillow جهت جلوگیری از حملات DoS مبتنی بر حافظه.
- [x] **محدودیت ابعاد**: حداکثر رزولوشن ۴۰۹۶ در ۴۰۹۶ پیکسل.
- [x] **حذف خودکار اطلاعات متادیتا و موقعیت مکانی (EXIF Stripping)**: بازتولید تصویر در فرمت بهینه WebP بدون داده‌های حساس GPS.

---

## ۶. یکپارچگی پایگاه داده و تراکنش‌ها (Database Integrity)

- [x] **قفل ردیفی همزمانی (`select_for_update`)**: در تراکنش‌های حساس سبد خرید، رزرو موجودی، سفارش، پرداخت و کوپن تخفیف.
- [x] **تراکنش‌های اتمیک (`@transaction.atomic`)**: اجرای کامل یا لغو کامل (Rollback) در صورت وقوع هرگونه خطای تجاری.
- [x] **شناسه‌های غیرقابل پیش‌بینی**: استفاده همگانی از `UUIDv4` به عنوان کلید اصلی جداول جهت مهار حدس متوالی شناسه‌ها.

---

## ۷. ثبت لاگ و نظارت امنیتی (Logging & Monitoring)

- [x] **فیلتر داده‌های حساس (`SensitiveDataFilter`)**: جایگزینی خودکار پسوردها، توکن‌ها و کلیدهای دسترسی در لاگ‌ها با `***REDACTED***`.
- [x] **پنهان‌سازی لاگ OTP در پروداکشن**: عدم نمایش متن کد یک‌بارمصرف در خروجی لاگ سرور هنگام `DEBUG=False`.
- [x] **ردیابی درخواست‌ها (`Request ID`)**: ثبت شناسه یکتای UUID برای هر درخواست جهت امکان ترکینگ و پیگیری رخدادهای امنیتی.
- [x] **عدم نشت اطلاعات سیستم در خطاهای ۵۰۰**: هندلر خطای سفارشی که پاسخ استاندارد `InternalServerError` بدون جزییات فنی برمی‌گرداند.

---

## ۸. امنیت فرانت‌اند Next.js

- [x] **کنترل مسیرهای بازگشتی (Open Redirect Prevention)**: اعتبارسنجی تمام پارامترهای `?redirect=` با متد `getSafeRedirectUrl`.
- [x] **ایمن‌سازی داده‌های ساختاریافته JSON-LD**: اسکیپ کردن کاراکتر `<` با `\u003c` در اسکریپت‌های ساختاری سئو جهت مهار XSS.
- [x] **گارد Edge Middleware**: اعتبارسنجی وضعیت احراز هویت و پرچم پرسنل برای تمام مسیرهای `/admin/*`.
- [x] **عدم افشای کلیدهای سروری**: استفاده منحصربه‌فرد از متغیرهای `NEXT_PUBLIC_API_URL` و `NEXT_PUBLIC_SITE_URL` در سمت کلاینت.

---

## ۹. زیرساخت داکر و شبکه‌بندی (Docker & Infrastructure)

- [x] **شبکه‌های مجزا**: جداسازی شبکه داخلی سرویس‌های پشتیبان (PostgreSQL و Redis) از پورت‌های عمومی غیرضروری.
- [x] **پایش سلامت کانتینرها (Healthchecks)**: پایش منظم وضعیت اتصال دیتابیس و ردیس از طریق اندپوینت `/api/v1/health/ready/`.
- [x] **عدم ذخیره کلیدها در گیت**: فایل `.env` و کلیدهای اجرایی در `.gitignore` ثبت شده و فایل نمونه `.env.example` راهنمای ایمن ارائه می‌دهد.
